SECTION 1: TASK 1.3 - LANDING ZONE ARCHITECTURE DECISION LOG
-------------------------------------------------------------------
[ENVIRONMENT ASSUMPTION]
Traditional ADF multi-resource groupings (Data Factory + Storage Accounts) are collapsed into a unified Microsoft Fabric SaaS Workspace. Medallion zones operate as distinct virtual layers inside a single logical container rather than separate physical resources.

[SECURITY ASSUMPTION]
Granular access control is managed via Fabric Workspace Roles (Admin, Member, Contributor, Viewer) combined with Item-Level Permissions, replacing traditional Azure RBAC and Key Vault secret management requirements for internal lakehouse data routing.

[NETWORK ASSUMPTION]
All data movements across the Bronze, Silver, and Gold layers execute natively over the optimized Microsoft Backbone Network using OneLake shortcuts. This completely eliminates the need for managing complex Azure Virtual Network (VNet) peering, Private Endpoints, or custom Integration Runtimes.

[MONITORING ASSUMPTION]
Telemetry and job runs are tracked globally via the Microsoft Fabric Monitoring Hub. This replaces distributed Azure Monitor, Log Analytics alerts, and custom ADF diagnostic pipeline logging matrices with a single operational dashboard view.

SECTION 2: TASK 1.4 - DATABRICKS-TO-FABRIC ARCHITECTURAL MAPPING
-------------------------------------------------------------------
This mapping log outlines the platform structural translations required to modernize a legacy Azure Databricks workspace over to a native Microsoft Fabric data estate platform:

1. WORKSPACE COMPONENT:
   - Databricks Asset: Azure Databricks Workspace (E2 Architecture / Control Plane)
   - Microsoft Fabric Translation: Fabric Workspace (Premium Capacity / Trial Capacity)
   - Architectural Note: Replaces individual cluster management nodes with a shared, automatically scaled SaaS workspace container.

2. STORAGE & STORAGE LAYER:
   - Databricks Asset: DBFS (Databricks File System) / ADLS Gen2 Mount Points
   - Microsoft Fabric Translation: OneLake (The OneDrive for Data)
   - Architectural Note: Replaces manual path mounting scripts with a single global, unified tenant file system layout.

3. CATALOG & METADATA MANAGEMENT:
   - Databricks Asset: Hive Metastore / Unity Catalog
   - Microsoft Fabric Translation: Fabric Lakehouse SQL Analytics Endpoint / Schema Catalog
   - Architectural Note: Tables automatically register their schemas across a multi-engine catalog without requiring manual external hive connections.

4. COMPUTE ENGINE & COMPOTATIONAL INTERFACE:
   - Databricks Asset: Databricks Interactive Clusters / Job Clusters (Spark Engine)
   - Microsoft Fabric Translation: Fabric Spark Pools & Interactive Sessions
   - Architectural Note: Eliminates manual driver/worker node sizing configurations by utilizing instant-on serverless live pools.

5. CODE DEVELOPMENT ORCHESTRATION:
   - Databricks Asset: Databricks Notebooks (.ipynb / %python %sql scripts)
   - Microsoft Fabric Translation: Fabric Notebooks (Native PySpark and Spark SQL cells)
   - Architectural Note: Code syntaxes match exactly, allowing PySpark scripts to run without structural code rewrites.

6. DATA STORAGE ENGINE FORMAT:
   - Databricks Asset: Delta Lake Tables (Liquid Clustering / Parquet files)
   - Microsoft Fabric Translation: Delta Lake Tables (Native OneLake V-Order Optimization)
   - Architectural Note: Fabric utilizes Delta Lake as its primary storage format, adding unique V-Order sorting algorithms to supercharge Power BI read speeds.

7. AUTOMATION & WORKFLOW SCHEDULING:
   - Databricks Asset: Databricks Workflows / Jobs Orchestration Engine
   - Microsoft Fabric Translation: Fabric Data Pipelines
   - Architectural Note: Uses drag-and-drop activity nodes to visually orchestrate and monitor script cells and tasks.

8. BUSINESS INTELLIGENCE CONSUMPTION LAYER:
   - Databricks Asset: Databricks SQL Dashboards / External BI JDBC/ODBC Direct Links
   - Microsoft Fabric Translation: Power BI Semantic Models (Direct Lake Mode)
   - Architectural Note: Bypasses slow JDBC database queries completely by allowing Power BI to read Delta parquet files straight out of storage in real time.
